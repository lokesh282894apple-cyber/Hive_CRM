1. WhatsApp via Meta Cloud API

Docs: developers.facebook.com/docs/whatsapp/cloud-api/get-started · Access tokens guide under WhatsApp Business Platform

Option A — Meta Cloud API (recommended — use this)

  1. Go to Meta for Developers → create or open an app → add product WhatsApp.
  2. On WhatsApp → API setup, connect a WhatsApp Business Account (WABA) and add / verify a business phone number.
  3. From API setup, copy and keep:
    • Phone number ID → CRM env META_WA_PHONE_NUMBER_ID
    • WhatsApp Business Account ID (for templates)
  4. Temporary tokens from “Generate access token” expire quickly — fine for hello_world test only, not production.
  5. Create a permanent System User token (Meta’s recommended path for direct developers):
    1. Meta Business Suite → Business settings → Users → System users → Add
    2. Assign assets: your App + WhatsApp account (full / manage WhatsApp Business accounts)
    3. Generate token with at least: whatsapp_business_messaging, whatsapp_business_management (add business_management if the UI offers it)
    4. Copy once → send securely to tech as META_WA_TOKEN (Vercel env)
  6. Send a test hello_world template from API setup to confirm the number works.
  7. Production number note: After adding + verifying a real business number in WhatsApp Manager, Meta may require an API POST /{PHONE_NUMBER_ID}/register with a 6-digit PIN before Cloud API sends. If test works but production number fails, ask tech to run registration with your token.

Option B — BSP (AiSensy / WATI / Interakt)

Not required. Only if leadership wants a BSP shared inbox. CRM already sends via Meta Cloud API without a BSP.

2. Email via Resend (transactional)

Docs: resend.com/docs/add-a-domain

  1. Create a Resend account → Domains → Add Domain.
  2. Prefer a sending subdomain (Resend best practice), e.g. mail.hiveschool.in or send.hiveschool.in.
  3. Open the domain’s Records tab. Add exactly what Resend shows to DNS (typically all three):
    • DKIM — TXT (often resend._domainkey…)
    • SPF — TXT on the send subdomain
    • MX — for bounce/return-path on that subdomain
    Do not invent SPF values or add Resend to your apex SPF unless Resend’s UI tells you to.
  4. Click Verify in Resend (often <15 minutes; DNS can take up to 72h). Use Resend’s dns.email checker if stuck.
  5. Optional: after verify, add DMARC at _dmarc.hiveschool.in starting with p=none.
  6. Create an API key → send to tech as RESEND_API_KEY.
  7. Agree From address on the verified domain, e.g. HiveSchool Admissions <admissions@mail.hiveschool.in> → tech sets EMAIL_FROM.

3. Meta Lead Ads → CRM (real-time)

Docs: developers.facebook.com/docs/marketing-api/guides/lead-ads/quickstart/webhooks-integration

3a. What CRM already expects

  • Webhook URL: https://hive-crm-sigma.vercel.app/api/leads/meta
  • Page access token → CRM Admin → Marketing → Connections (platform: meta)
  • Webhook verify token → same Connections page (keep identical in Meta + CRM)

3b. Steps (current Meta flow — do not skip Page install)

  1. Meta for Developers → your app → add Webhooks.
  2. Subscribe object Page, field leadgen.
  3. Callback URL: https://hive-crm-sigma.vercel.app/api/leads/meta
  4. Verify Token: invent a long random string → save the same string in CRM Connections → Meta webhook verify token.
  5. Click Verify and Save (Meta GET-challenges the CRM URL — must succeed).
  6. Generate a Page access token with permissions typically including: leads_retrieval, pages_manage_metadata, pages_show_list, pages_read_engagement (and ads-related scopes if App Review requires them for your setup).
  7. Install the app on the Facebook Page (dashboard subscribe alone is not enough — Meta docs require this or webhooks won’t fire):

    POST https://graph.facebook.com/v25.0/{PAGE_ID}/subscribed_apps
    subscribed_fields=leadgen&access_token={PAGE_ACCESS_TOKEN}

    Use Graph API Explorer (POST) or ask tech to run the curl. Prefer current Graph version (v25.x as of early 2026); older tutorials saying v17/v21 still work until that version is deprecated.
  8. In CRM → Admin → Marketing → Connections:
    • Platform: meta
    • Account / Page ID
    • Access token: Page token
    • Save
  9. App Review: testing on Pages you admin works in development; production lead retrieval for live ads usually needs leads_retrieval approved. Start App Review early if ads run under other admins.
  10. Publish a test Lead Ad form → submit → lead in CRM within ~1 minute with campaign attribution.
  11. Submit the same phone twice → one lead, two touchpoints (dedup).

4. Website / landing page forms

  1. Send tech a spreadsheet of every live form URL (main site + LPs).
  2. Each form must POST JSON to:
    https://hive-crm-sigma.vercel.app/api/leads/website
    Header: Authorization: Bearer {CRM_TRACK_API_KEY} (tech provides the key).
  3. Minimum fields: name, phone. Recommended: email, source, programme, session_id, utm_source, utm_medium, utm_campaign, utm_content.
  4. From a UTM-tagged link, submit one test lead per form. Confirm on the lead profile + Marketing tab.

Field map for developers: docs/website-forms-audit.md in the CRM repo.

6. Read AI on interview Meets

Docs: support.read.ai → Getting Started with Webhooks. Plans: Pro / Enterprise / Enterprise+ only.

  1. Upgrade Read AI to Pro (or higher) and create / use an admissions Workspace.
  2. Connect Google Calendar for the same account(s) that receive CRM Meet invites (shared admissions calendar / interviewers).
  3. Enable auto-join for Google Meet (Account / Workspace settings → Meeting recording → Auto-join). Prefer joining meetings where the account is invited/host.
  4. Create a Workspace webhook (not only a personal user webhook — so all interviewers’ meetings flow):
    • Path: Integrations → Workspace → Webhooks (admins/owners only)
    • URL: https://hive-crm-sigma.vercel.app/api/read-ai/webhook (HTTPS only)
    • Trigger: meeting_end (required for report attach)
    • Name: ASCII only (no emoji)
    • Email on the Read account must be verified
  5. Copy the webhook signing key from Read’s webhook settings → send to tech as READ_AI_WEBHOOK_SECRET.
    Read signs deliveries with header X-Read-Signature (HMAC-SHA256). Tech stores the key in Vercel — you do not invent a Bearer token in the Read UI.
  6. Acceptance test: book R1 in CRM → conduct Meet → Read joins → report link appears on that round within minutes.
CRM already creates Calendar + Meet + calendar_event_id. Matching depends on calendar/Meet identity in the webhook payload — keep using the shared admissions calendar.
